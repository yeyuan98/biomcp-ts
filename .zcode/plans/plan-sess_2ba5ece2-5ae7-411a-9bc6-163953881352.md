## WP-9 first — CI surfacing + process docs (the standardization you asked for)

**Write boundary:** `.github/workflows/ci.yml`, `scripts/ci/integration-summary.ts` (new), `docs/development/CI.md`, `docs/DEVELOPMENT.md`, `src/__tests__/README.md`.

1. **Split the integration tier into its own visible, non-blocking job.** Today it's a `continue-on-error` step inside the required `ci` job — failures hide behind a green check (exactly how we missed things). Restructure:
   - Job `ci` stays exactly as named (required gate: typecheck, unit, build, audit) minus the integration step.
   - New job `integration` (parallel, no dependencies): runs `npm run test:integration` with output tee'd to `integration.log`, then an `if: always()` summary step.
   - **No `continue-on-error`** on the new job: a failure renders as a clear red ✗ named `integration` in the PR checks list, but since it's not in any required-checks list it does not block merging (mergeStateStatus UNSTABLE, mergeable stays true). Defensive fallback if branch protection turns out to block in practice: set job-level `continue-on-error: true` (summary still generated; visibility slightly reduced) — verified empirically on this PR and documented whichever way it lands.
2. **Step Summary for one-click review.** New `scripts/ci/integration-summary.ts` (run via `node --import tsx`, typechecked by the existing `tsconfig.scripts.json` pipeline): parses the tee'd jest log and writes Markdown to `$GITHUB_STEP_SUMMARY` — verdict header ("✅ all keyless integration suites green" or "❌ N failures — triage before merging"), a table of failed suites + test names + the `Tests:` totals, and the triage-rubric reminder with a link to `docs/development/CI.md`. Parser must handle the exact jest output shape — validate it offline against the 14 real CI job logs I have cached in `/tmp/cilogs/*.log` (plus a synthetic clean-pass sample), asserting it extracts the known failure sets (e.g., Szostak/OPS/gene_enrich signatures).
3. **Process documentation.**
   - `docs/development/CI.md` — new "Integration tier & merge checklist" section: what each check means (`ci` = required gate; `integration` = advisory-but-mandatory-review); the standardized pre-merge step: *open the `integration` job → read the Step Summary → triage every failure into one of three buckets* — (a) upstream (rate-limit/timeout/geo-block from runner IPs; note it in the PR), (b) test-design (brittle assertion; file an issue), (c) code defect (fix before merge) — with today's real examples as the rubric (ensembl timeouts = upstream; Szostak NaN / OPS undefined-vs-false = test-design; genes_overlap 11>10 = code defect). Also: how to reproduce locally (`make test-integration`) and why local WSL2 clock-skew makes CI authoritative for flake triage.
   - `docs/DEVELOPMENT.md` Tests section + `src/__tests__/README.md`: short pointers to the checklist and the summary location.
