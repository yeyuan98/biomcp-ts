## [Unreleased]

### Added

- **`article_search` trailing full journal names are rewritten to NLM abbreviations automatically, with disclosure** (`scripts/build/fetch-journal-list.ts` (new), `src/entities/article/search/journal-titles.ts` (new), `search/pubmed.ts`, `search/europepmc.ts`, `search/index.ts`, `src/server/tools/article.ts`) — fixes #121. PubMed journal scoping only matches NLM abbreviations, so a full journal name in the query was silently dropped or reinterpreted by term translation — "Huntington disease New England Journal of Medicine" returned off-topic wrong-journal papers with no warning. Mechanism: a build-time script (wired as the `prebuild` npm hook, so every `npm run build` — and `prepack`, which calls build — refreshes it) downloads NLM's live J_Entrez.gz journal list (~42k records, regenerated daily), normalizes titles (casefold; strip leading the|a|an; strip one trailing parenthetical; collapse whitespace), and emits a gzipped TSV asset (`dist/assets/journal-titles.tsv.gz`, shipped in the npm package, never committed) mapping normalized titles to MedAbbrs; the download fails LOUD (exit 1, retryable message) on non-200/timeout/invalid-gzip, and entries whose normalized title maps to more than one distinct MedAbbr, or whose MedAbbr contains a parenthesis, are quarantined (dropped) so a rewrite can never silently change the target journal. At query time, when a pubmed or europepmc-journal query ENDS with a full journal name recognized from the list, the phrase is hoisted into explicit field syntax — `<rest> N Engl J Med[Journal]` on PubMed, `(<rest>) AND JOURNAL:"N Engl J Med"` on Europe PMC — preserving the rest of the query verbatim, and every rewrite is disclosed in the envelope `warnings` channel ("Journal phrase rewritten: '…' → '…'"); a missing asset (dev without a build) silently disables the feature (empty map, no crash), mid-query or unrecognized journal names never rewrite, and the preprint/semantic_scholar/arxiv/pubtator/litsense paths are untouched. The journal-scoping docstring now tells the truth: recognized trailing full names are auto-rewritten; otherwise supply the NLM abbreviation or `Abbr[Journal]` field syntax — unmatched full names are not matched by PubMed/EuropePMC.

### Changed

- **`drug_search` rows carry the true FDA UNII in `unii` and the CAS registry number in a new `cas` field (BREAKING)** (`src/entities/drug.ts`, `src/__tests__/entities/drug.test.ts`, `src/__tests__/integration/tools/drug-tools.test.ts`) — fixes #123. MyChem's `unii` sub-document holds two distinct identifiers — `registry_number` (the CAS registry number) and `unii` (the FDA UNII) — but the transform mapped the output `unii` field from `registry_number` while the `fields=` projections never requested `unii.unii` at all, so every `drug_search` row's `unii` actually carried the CAS number (live: imatinib → "152459-95-5" instead of BKJ8M8G5HI; aspirin → "50-78-2" instead of R16CO5Y76E) — a wrong identifier close enough in shape to a UNII that downstream FDA/SRS joins silently mismatched. Both members are now requested in the search and get `fields=` lists, and rows expose `cas: unii.registry_number` plus `unii: unii.unii` (each optional, matching source availability; the row-richness counter used by duplicate collapse counts them both). Companion honesty fix in `drug_get`: the CAS no longer pollutes the generic `aliases` array (which stays reserved for true name synonyms) — it is reported as `cas` on the result, with the cross-hit consolidation backfilling `cas` the same way it backfills `chembl_id`. Migration: consumers reading `unii` for the CAS number should read `cas`; `unii` now carries the FDA UNII.

### Fixed

- **`article_search` `dateRange` is now enforced on pubmed and europepmc** (`src/entities/article/search/pubmed.ts`, `src/entities/article/europepmc-shared.ts`, `src/server/tools/article.ts`) — fixes #120. The filter was silently ignored on both backends: Europe PMC searched `pub_year:[Y TO Y]` (print year) while rows display `firstPublicationDate`, and PubMed's esearch `datetype=pdat` window matches epub dates while rows display the print/issue `<PubDate>` — in both cases out-of-window records were returned with no warning. Europe PMC (journal and preprint paths) now sends `FIRST_PDATE:[<from> TO <to>]` at day granularity (`*` for open bounds) — the very field rows display. PubMed overfetches (`retmax = min(limit*2, 100)`) when a range is active and post-filters rows client-side on the DISPLAYED date via a pure `isWithinDateRange` helper (year compared always; month/day only on boundary years and only when the date carries them; unparseable MedlineDate/undated rows pass conservatively), then records what happened in the envelope `warnings` channel — rows removed + the range (with paging/limit guidance when the page comes back short), or an explicit zero-in-window note. The dateRange tool docstring now discloses the pubmed epub-vs-print post-filter.
- **`gene_search` offset past the end returns an empty page instead of wrapping to page 0** (`src/entities/gene.ts`) — fixes #122. The #99 single-token prefix fallback fired on any zero-hit page, but a zero-hit page means two different things: the token matched nothing (the fallback's job) or `offset` ≥ `total` (end of pagination) — mygene keeps reporting the full `total` for out-of-range offsets (live-verified: `q=BRAF&from=20` with `total=16` → `hits: []` with `total` intact). Because the fallback also re-requested with `from` hardcoded to 0, `gene_search({query: "BRAF", offset: 20})` silently returned page 0 again, so agents paging with `offset += limit` never terminated and re-read the same rows as "new". The fallback now fires only on a genuinely empty result (`total === 0`, the field mygene always returns) and the retry carries the caller's offset. The chromosome-filter path already paginated correctly (bounded upstream scan + local offset/limit slice; its fallback gates on upstream page-0 emptiness) and is unchanged.

## [1.6.0-alpha.3] - 2026-10-17

QA-campaign hardening: 11 upstream-verified fixes across search filters, ID resolution, contract honesty, and connection reliability, plus the deferred preprint full-text tool.

### Added

- **New `preprint_fulltext` tool — on-demand bioRxiv/medRxiv full text (JATS)** (`src/entities/article/detail/preprint-fulltext.ts`, `preprint-fulltext-cache.ts`, `src/server/tools/article.ts`) — implements #44. Fetches the official `/details` record from api.biorxiv.org, then downloads the JATS XML from www.biorxiv.org under a strict politeness gate: ≥3 s spacing (dedicated token bucket), one bounded retry, and a `max(60 s, Retry-After)` cooldown after any 429/403/Cloudflare-1015 (challenge pages served with HTTP 200 are detected, scanning only the first 1 KB so legitimate prose is never misclassified). Downloads are cached in a separate `(doi, version)`-keyed store (JATS per version is immutable; atomic writes, traversal-safe keys, count-based LRU) — the PMC fulltext store's write-only contract is untouched. Responses mirror `article_get` fulltext file/inline shapes and always carry `doi`, `version`, `license`, `license_url`; under rate limiting the tool returns an honest `rate_limited` envelope (or serves the newest cached version with a disclosure) instead of hammering the host. `article_get`'s preprint link-only stub now points at the tool.
- **`variant_get` returns all alleles for multi-allelic rsIDs** (`src/entities/variant.ts`, `src/server/tools/variant.ts`) — fixes #101. MyVariant serves one doc per allele (e.g. rs28934575 → 3 ClinVar alleles); the client previously picked one (gnomad-preferred) and silently discarded the rest, hiding Pathogenic records behind an Uncertain-significance top level. Multi-doc responses now attach `alleles[]` (one compact core record per doc, exactly mirroring `variant_search`'s extraction, so the two tools can never disagree) plus a `_warning` naming the allele the top-level record reflects; the docstring documents allele-qualified HGVS input (transcript version must match the indexed snpeff annotation — `NM_000546.5` resolves, ClinVar's `.6` does not).
- **`gtex_eqtl` empty results now carry a cross-tissue diagnostic note** (`src/entities/gtex.ts`, `src/server/tools/gtex.ts`) — fixes #106. Verified against GTEx v10: TP53 genuinely has zero significant cis-eQTLs in Whole_Blood but 51 across 9 other tissues (Kidney_Cortex 17, Nerve_Tibial 13, …) — an empty answer is valid science, not a mapping failure. Zero-row tissue queries now make one all-tissues follow-up and attach `note` listing where associations do exist (top-5 + "and K more") or stating none exist anywhere; non-empty paths issue no extra call. The gtex connection also gained `retry: { attempts: 2 }` (it was the only source without one).
- **`ensembl_region` echoes its effective variation coverage** (`src/entities/ensembl.ts`, `src/server/tools/ensembl.ts`) — part of #104. Large requests now return `effective_variation_window` (the window actually queried) and `variation_truncated` (naming the dropped span) so callers know coverage was reduced; per-feature failures surface as `feature_errors` instead of failing the whole call.
- **`gene_search` discloses scan-window truncation** (`src/entities/gene.ts`) — part of #98. When the bounded 3-page/300-hit upstream scan exhausts before enough chromosome-filtered rows are collected, results carry a `_warning` stating the scan window was exhausted.
- **Connection-layer reliability controls: retry budgets and per-source concurrency caps** (`src/connections/retry.ts`, `concurrency.ts`, `registry.ts`, `rest.ts`, `graphql.ts`, `base.ts`) — phase 1 of #107. `withRetry` honors an optional per-source `retryBudgetMs` (the first attempt always runs; retries stop once the budget is blown), cutting worst-case logical-request stacks from ~63.5 s (eutils 4×15 s) to ~30.5 s. A new FIFO `BoundedSemaphore` (acquired per attempt, so backoff sleeps hold no slot and retried requests re-queue at the back) caps fan-out per source: semantic_scholar 3, ensembl 4, eutils 6. All defaults preserve current behavior for unconfigured sources.

### Changed

- **`gene_search` chromosome filter no longer drops the text query; 0-hit single-token queries get a prefix fallback** (`src/entities/gene.ts`) — fixes #98 and #99. MyGene v3's query parser discards every other clause whenever a genomic-interval token is present, so the `AND chrN:…` clause built for the chromosome filter silently made results query-independent (regression from the #76 fix in alpha.2). The interval clause is never sent now: the plain dismax query goes upstream and hits are filtered client-side on `genomic_pos.chr` (object-or-array aware) with bounded paging and offset/limit slicing in relevance order. Separately, MyGene dismax is exact-token only (`BRCA` → 0 hits): single-token zero-hit queries retry once with `symbol:<escaped-token>*` (`BRCA` → BRCA1, BRCA2, …), and the chromosome filter applies to fallback results too.
- **`disease_get` UMLS CUI records resolve to real names via MedGen enrichment** (`src/entities/disease.ts`, `src/server/tools/disease.ts`) — fixes #100. mydisease serves a nameless UMLS stub for CUI lookups (e.g. `umls:C0018794` → `HP:0012722` with no name, no mondo/DO data), which the resolver then echoed as `name: "C0018794"` with a false `ontology: "disease_ontology"` — a correct resolution dressed as nonsense (C0018794 is *Heart block*; the fix was verified live against NCBI MedGen, and the docstring example no longer implies otherwise). Nameless stubs now enrich name/description via MedGen esearch/esummary on the existing eutils connection (guarded by `conceptid === cui`), report `ontology: "umls"` honestly, never echo the input id as a name, and attach `_warning` if enrichment fails. `disease_trials` query resolution benefits automatically.
- **HTTP errors surface upstream detail; ensembl timeout/retry rebalanced** (`src/connections/rest.ts`, `src/connections/registry.ts`, `src/server/tools/ensembl.ts`) — fixes #102. Non-OK responses previously discarded the body and substituted a generic hint ("the record may not exist") — actively misleading for, e.g., Ensembl VEP coordinate-parse 400s whose body explains exactly what failed. Both `requestOnce` and `postOnce` now append defensively-parsed upstream error text (` — Upstream: <msg>`, JSON-prefixed bodies only, 300-char cap, never crashes on bodyless/HTML responses), keeping the legacy message intact. The ensembl connection moves to `timeoutMs: 30000` with `attempts: 2` (valid VEP calls observed at 6.6–23 s — the old 15 s cap aborted legitimate calls into retry storms), and the `ensembl_consequence` docstring states the per-species input rules (a RefSeq accession must belong to the target species; invalid HGVS now surfaces the explanatory upstream message).
- **`ensembl_region` splits feature requests and caps the variation window** (`src/entities/ensembl.ts`) — fixes #104. One combined `/overlap/region` request made the dense-locus variation sweep (~95k rows / 23 MB / 26–28 s) exceed every timeout deterministically (the reported 46–52 s failure was exactly 3×15 s retries). Gene/transcript features now fetch full-span in parallel with a variation request capped to a 50 kb window centered on the region midpoint — the issue's 250 kb repro went from a deterministic timeout to 13.5 s with BRAF present and the truncation echoed.
- **`article_get` fulltext contract documented to match the implementation; `oa_status` echoed** (`src/server/tools/article.ts`, `src/entities/article/detail/fulltext.ts`) — fixes #105. The docstring conflated `fulltext.status` (implemented: `available | unavailable` + a `reason` enum) with the oa section's five-value vocabulary; paywalled-vs-not-in-PMC is a `reason` distinction, not a `status` one. The description now states the real enums, attributes the five-value vocabulary to `sections.open_access.status`, documents the `oa`→`open_access` / `graph`→`citation_graph` response-key mapping and the inline array-of-sections shape, and the fulltext result echoes `oa_status` in all construction paths so the access nuance is visible without requesting the `oa` section. Response keys are unchanged.
- **Tool-level deadlines abort work; MCP cancellation is threaded** (`src/server/tools/utils.ts`, `article.ts`, `trial.ts`, `gene.ts`, `fetch-utils.ts`, tool registrations) — phase 2 of #107. `withToolTimeout` raced a timer without aborting, leaving zombie fetches retrying in the background (now holding phase-1 semaphore slots); it aborts via `AbortController` now (the duplicate helper in `article.ts` is gone), `fetchWithTimeout` settles at the deadline even when the callee ignores the signal, `withTimeout` aborts the loser (federated search legs converted to signal-bearing form; partial-results semantics unchanged), and trial's dead 8 s section race actually aborts. Tools without any deadline gained one — trial 45 s; gene/disease/drug/variant/pdb 40 s — sized against the phase-1 ceilings, and MCP `extra.signal` cancellation reaches the tool layer (`AbortSignal.any`).

### Fixed

- **`patent_search` titles no longer contain raw USPTO highlight markup** (`src/entities/patent/search/ppubs.ts`, `ppubs-client.ts`) — fixes #103. USPTO ppubs embeds `<span term="…" class="highlightN">…</span>` wrappers in `inventionTitle` regardless of the highlights flag (verified with `highlights: '0'`), including malformed doubled quotes (`term=""mrna""`). ### Changed

### Fixed

Unit tests pin both URL forms (including that the unsplit full string never appears); the live integration test asserts `hgvsc: "NM_004333.4:c.1799T>A"` returns BRAF V600E (rs113488022, live: exactly 1 hit).

All ten search tools whose schema takes a required free-text `query` (`patent_search`, `article_search`, `drug_search`, `gene_search`, `disease_search`, `trial_search`, `geo_search`, `genbank_search`, `sra_search`, `discover`) now declare `z.string().trim().min(1, 'Query must be a non-empty string after trimming')`, so the MCP SDK rejects the call with `InvalidParams` before the handler — and any upstream request — runs, mirroring the repo's established schema-level rejection pattern (accession regexes, `variant_search` enums). Two classification gates preserve observable behavior exactly: abort/timeout rejections (`AbortError`/`TimeoutError`, e.g. the 15 s `AbortSignal.timeout`) pass through untouched — same object, name, and message as before — keeping the callers that pin `name === 'AbortError'` (geneGet) and the `/abort|timeout/` message classifications (gene enrichment, server error formatting, section fetches); and rejections whose message carries no network signature keep today's raw escape and non-retryable classification, so retry counts and their real-backoff timing budgets are unchanged (every real-world Node fetch rejection — `fetch failed` with its `cause.code` — matches the signature and is wrapped). HTTP-status errors, GraphQL `errors[]` wrapping, and retry behavior are unchanged.
- **Federated citation cache key ignored `limit`** (`src/entities/article/citation/cache.ts`, `src/entities/article/citation/index.ts`) — the cache key was built from id/direction/source-mode/year only, so a `limit=5` call cached its 5-record result and every later `limit=50` call for the same article was served the truncated entry for the full 10-minute TTL. `getCitations` now includes its resolved limit in the key (`…|l50`), so different limits never share an entry; `buildCacheKey` appends the limit only when one is passed, keeping its documented legacy shape for callers that omit it.
- **Tool-layer section limiting mutated results still referenced by the citation cache** (`src/server/tools/utils.ts`, `src/server/tools/{article,trial,patent,disease,gene}.ts`, `src/entities/article/citation/index.ts`) — `applyLimit` sliced arrays in place on the passed `sections` object, but `article_get` stores the federated citation result (the cache's own object) directly into `sections.citation`, so every limited reply permanently truncated the cached arrays for the TTL. `applyLimit` is now non-mutating and returns a new sections object (copy-on-write per section: only sections that actually get an array sliced are copied; untouched sections keep their identity), all five tool callers use the returned value, and the citation cache additionally stores and returns private copies of its top-level arrays so a caller can never corrupt what the cache serves next. No behavior change for trial/patent/disease/gene sections beyond no-longer-mutating inputs.
- **`discover` result ranking and empty-record emission** (`src/entities/cross-entity.ts`, `src/server/tools/utility.ts`) — the `discover` tool previously pushed each backend's first hit verbatim (mygene/myvariant/mychem/mydisease default order), so substring name matches won over canonical records (e.g. `discover("melanoma")` resolving to gene BAGE "B melanoma antigen" instead of a canonical hit) and a backend hit with neither a name nor an identifier was emitted as an empty record (`{"entity_type":"drug","identifier":"","name":"","source":"mychem"}`). Each backend arm now requests up to 5 candidates and selects via a local `pickBestMatch` helper: a candidate whose symbol/name/label equals the query exactly (case-insensitive, whitespace-trimmed) is preferred wherever it ranks in the list; otherwise the backend's first candidate with a non-empty name or identifier is used (the previous deterministic behavior, so multi-word queries do not regress); candidates empty on both fields are skipped, and a backend with no usable candidates (or an erroring one) is omitted silently — discover never emits empty records. Every record now carries a `matched_on` field documenting why it was selected: `"exact"` (name/symbol equals the query) or `"first"` (backend's first non-empty hit); the OLS4 fallback arm reports the same rule from its labels. The `discover` tool description documents the exact-match preference and the new field. Concept-splitting for `discover` remains out of scope here and is deferred (issue #65). Unit tests in `src/__tests__/entities/cross-entity.test.ts` cover exact-match preference over an earlier substring hit, the first-non-empty fallback for multi-word queries (including skipping a nameless first mychem hit), and the all-empty-candidates case emitting no record for that entity type.
- **`drug_search` result quality: name-less rows, case duplicates, and salt-form variants** (`src/entities/drug.ts`) — MyChem records whose only name-bearing annotation is an FDA orphan designation were invisible to the old field projection and transformed into `{"name": ""}` rows that buried exact matches (GitHub issue #63). The search projection now requests `fda_orphan_drug` and `transformMyChemHit`'s name fallback chain extracts the designation's `generic_name` as a last-resort name, placed after the curated ChEBI/UNII/ChEMBL/NDC names and before the UNII registry number (orphan designation is a weaker identity source than any curated name; `trade_name` is deliberately unused). Live-verified on mychem.info: each orphan entry carries a usable `generic_name` (e.g. `"pembrolizumab"`, `"artesunate"`) alongside indication-only text, and orphan-only records exist with no chebi/unii/ndc at all (e.g. `_id FIHJKUPKCHIPAT-UHFFFAOYSA-N`); entries lacking `generic_name` still yield an empty name and are dropped by the new filter. Search results are then normalized and deduplicated through the new exported helpers `drugIdentityKey()` (ChEMBL id → InChIKey → case-normalized, salt-stripped name) and `collapseSaltVariants()` (rows with empty/whitespace names dropped; case variants and salt/ester forms — mesylate/methanesulfonate, fumarate, tosylate, hydrochloride/HCl, sulfate, sodium, phosphate, citrate, tartrate, maleate, succinate, acetate, besylate, matched as trailing whole-word tokens only, never substrings, stripped iteratively — collapse onto one row; the survivor is the record with the richest identity: ChEMBL id, then InChIKey, then most populated fields, with deterministic shortest-name then lexicographic tie-breaks). The limit is not refetched/refilled after filtering — returning fewer than `limit` rows is accepted. Unit tests in `src/__tests__/entities/drug.test.ts` (orphan-only name-less rows dropped, orphan `generic_name` fallback, case/salt collapse policy pinned incl. survivor rationale, whole-word-vs-substring and leading-token guards, distinct-drugs-stay-separate sanity, empty-name filter).

Known issue (deliberate, deferred): the EuropePMC search backend likewise ignores `offset` — its pagination is cursorMark-based, and migrating it to page windows deserves its own change.
- **HTML entity decoding in PubMed records** — numeric character references (`&#x3b2;`, `&#xe9;`, `&#xa0;`) in titles, abstracts, and authors are decoded to real UTF-8 (`β`, `é`, U+00A0) by enabling `htmlEntities` on the XML parser; XML-predefined entities (`&amp;` etc.) keep decoding as before.
- **LitSense records no longer fake an abstract** — LitSense returns one sentence-level full-text match per record with no title/journal/authors; that sentence previously shipped as `abstract`, causing downstream agents to fabricate titles from it. LitSense records now use the common article schema with fields it does not provide simply absent (`pmid`, `pmcid`, `score`, `source`). The backend is retained for its unique semantic full-text discovery.

## [0.7.0] - 2026-08-29

### Added

- **Biowasm: MCP progress notifications, cancellation, and large-input safety for the analysis tools** — root cause of the agent-test F1 cascade: a full-stream count on a sample-dense cohort VCF (measured envelope: ~0.9 MB/s — 206 MB in 228 s with ~11 GB of text expansion at 2,504 samples; BAM streams at ~110 MB/s, 311 MB in 2.9 s, and VCF headers read in 0.12 s) outlives the MCP client's 60 s deadline, the client's `notifications/cancelled` was ignored, and the zombie run then blocked the single-worker serialization queue for its full 10-minute timeout, cascading every later call into client-side timeout errors. Four additive mechanisms: (1) **progress notifications** — worker→host progress (cumulative bytes read, ≥5 s cadence, elapsed + stderr tail in the message) is forwarded as `notifications/progress` when and only when the client sent a `_meta.progressToken` (measured: progress-bearing calls outlive the deadline — a 100 s probe completed at 100.1 s when reporting every 5 s and died at 60.0 s when silent); (2) **cancellation** — client cancel/timeout aborts immediately: queued runs reject before start, running runs kill the worker (`BiowasmCancelledError`; a fresh worker respawns on the next call, disk artifacts and indexes persist), freeing the queue in milliseconds instead of blocking it; (3) **estimate-based large-input gate** on `analysis_bam_summary`/`analysis_bcf_summary` only (in-band content and artifact sources never gated; `analysis_biowasm_cli` never gated — it is the escape hatch) — a documented throughput model (BAM ≈ 110 MB/s; VCF ≈ 0.9 MB/s × 2504/sampleCount clamped to [0.9, 110] MB/s, sample count sniffed from the header) estimates the full-stream time and returns guidance with alternatives when it exceeds 45 s; the new additive `proceed_on_large_input` flag opts into the long stream; (4) **`bcf_summary` index fast path** — `bcftools index -s` runs first when a sidecar is present: its summed records column is the variant count and the streaming pass is skipped entirely (failures are non-fatal and fall back to the gated streaming count, also fixing the q01-era bug where a successful count was discarded because `index -s` errored afterward). Engine timeouts are now activity-based: `ANALYSIS_BIOWASM_TIMEOUT_MS` (default 600000) becomes an inactivity deadline reset by progress, joined by the new absolute ceiling `ANALYSIS_BIOWASM_MAX_RUN_MS` (default 3600000) so GB-scale jobs with live progress can finish. Guide: [docs/BIOWASM-ANALYSIS.md](docs/BIOWASM-ANALYSIS.md).
- **Agent-test harness (`agent-test/`)** — standardized user-agent (LLM) E2E tests for the MCP tools, executed through the host `opencode` CLI: a dependency-free runner + objective grader (`run.mjs`) with a 12-check vocabulary (`tool_seq`, `group`, `text`/`number_near`/`text_number_count`, `args`/`args_rel`/`json_path`, `tool_count`, `no_such_tool`, `status`, and manual `rubric` with `PASS*`/adjudication flow), sha256-pinned fixture provisioning via per-test `resources.download.sh` (1000 Genomes CC0 public twins; auto-download or `AGENT_TEST_DATA` pre-provision), and per-invocation provenance (git HEAD, opencode version, global-config hash, host bio-tool probe). Ships a 14-test biowasm agent-usability suite (`biowasm-q01`…`q14`, L0–L3; guide: [agent-test/README.md](agent-test/README.md)). First-round findings — the large-file MCP timeout cascade, broken `variant_types` on the pinned bcftools 1.10, and validation errors that don't name the offending field — are documented in the 2026-08-29 run report, not fixed here.

### Fixed

- **Biowasm: indexless depth on order-violating input now errors instead of doubling** — `analysis_bam_view_region` with `mode="depth"` on indexless sources previously emitted doubled, self-contradictory output (a zero-filled pass followed by the correct pass, e.g. 42 rows for a 21-position region) when the input's read order regressed across references: vanilla samtools 1.21 intends to reject such input ("Data is not position sorted") but that guard is unreachable for cross-reference regressions in `bam2depth.c` (`dh->last_ref` is overwritten before the check runs). The analyzer now detects the doubled signature (a repeated `(chrom, pos)` row — impossible on valid single-interval `depth -a -b` output, which is strictly monotone per contig) and fails with an actionable error: provide an indexed source (sibling `.bai`), re-sort via `analysis_biowasm_cli` (`samtools sort`), or use `mode="count"`/`"reads"`, which tolerate any order. Native `depth -a -b` args and the indexed `-r` path are unchanged; valid coordinate-sorted input produces byte-identical output. Known limitation: a region large enough to hit the 2 MB capture cap before the doubled section can hide the duplicate, leaving flagged (`is_truncated`) output.

## [0.3.0] - 2026-08-24

### Breaking

- **Disease**: `disease_get` `survival` section removed — it targeted a fabricated endpoint. Remaining sections: `gene_associations`, `phenotypes`, `pathways`.
- **Variant**: `variant_get` `alphagenome_scores` section now returns an `{ _error }` stub pending native gRPC reimplementation (`ALPHAGENOME_API_KEY` is no longer read anywhere).
- **Search filters**: `gene_search` `gene_type`, `drug_search` `drug_type`, and `disease_search` `disease_type` filter parameters removed — upstream APIs silently ignored them.
- **Citations**: Crossref forward-citation lists removed (the Crossref REST API dropped the `references` filter). Crossref still supplies citation counts and backward references; forward citation lists come from Europe PMC, OpenCitations, and Semantic Scholar.

### Fixed

- Europe PMC citation/reference parsing, search PMID mapping, and citation-count query.
- OpenCitations migrated to the v2 API (`/citations/`, `/references/`, `/citation-count/`).
- DisGeNET: `/gda/summary` endpoints, raw-key auth, and response parsing.
- CIViC clinical-variant GraphQL query.
- OncoKB `hugoSymbol` query params.
- MyVariant `gnomad_exome.af.af` / `gnomad_genome.af.af` frequency fields.
- LitSense `limit` param.
- PubTator server-side pagination.
- PubMed `esearch` paired date bounds (`mindate`/`maxdate`).
- EPO OPS throttle-reason branching and HTTP 429 handling.
- Wayback snapshot gating: captures with known 4xx/5xx status or `available: false` are skipped before playback.
- OpenTargets 403 edge blocks fixed by sending an identifying User-Agent.
- `patent_search` tool timeout raised 30s → 60s (seminal prior-art mining is default-on).

### Changed

- Connection layer: typed errors, registry-driven retry, and unified timeouts; proxy-init failures are now surfaced instead of silently swallowed.
- MCP handshake version now matches the `package.json` version (was hardcoded `1.0.0`).
- Source registry pruned 61 → 34 sources (unused entries and fabricated transports removed).

### Removed

- SEER, AlphaGenome, and gRPC plumbing.
- Dead fixture-replay test mechanism.
